# ToolHub Studio 사용 가이드 (사용자용)

> 대상: Studio 사용자(개발자). 요구조건을 입력하면 Claude가 요구조건·코드·testcase를
> 생성하고, 본인 브랜치에 커밋 → stage(기존 CICD)로 빌드/검증까지 돌린다.
> 최초 1회 AWS/GHE 연결만 하면 이후는 채팅처럼 사용한다.

## 0. 최초 연결 (1회)

Studio는 **본인 명의**로 Bedrock(AWS)과 GHE에 접근한다(봇 계정 없음).

### 0.1 AWS 연결 (Bedrock)
1. 우상단 “AWS 연결” 클릭 → 승인 링크가 새 탭으로 열림.
2. 브라우저에서 승인(사내 SSO 페더레이션 시 클릭 1회).
3. 배지가 “AWS 연결됨”으로 바뀌면 완료.
- 세션 만료 시 배너가 뜨면 다시 “AWS 연결”을 눌러 재승인한다(만료 30분 전 자동 갱신
  시도가 있으나, 세션 자체가 끝나면 재승인 필요).

### 0.2 GitHub(GHE) 연결
- **방법 A (권장) — OAuth**: “GitHub 연결” → 승인 → 자동 완료. 토큰은 자동 갱신된다.
- **방법 B (폴백) — PAT**: OAuth가 막혀 있으면 개인 PAT를 발급해 등록.
  - GHE → Settings → Developer settings → Personal access tokens → `repo` 범위로 발급.
  - Studio의 PAT 입력란에 붙여넣기(유효성 검증 후 암호화 저장).

### 0.3 작업 브랜치 설정
- 설정에서 **repo + 본인 브랜치**를 지정한다(예: `feature/my-work`).
- 보호 브랜치(main 등) 지정 불가, 다른 사용자가 이미 쓰는 브랜치도 지정 불가.
- 브랜치가 없으면 생성해 준다.

## 1. 기본 흐름

```
요구조건 입력 → [Step 2] 요구조건 확정 → [Step 3] 코드·testcase 생성
→ [Step 3.5] 리뷰 승인 → [Step 4] 커밋/push → stage 빌드·검증
→ [Step 5] CI 결과 자동 회신 → 실패면 같은 studio에서 다음 회차로 반복
→ 통과하면 “PR 생성” 버튼으로 본인 명의 PR
```

- **studio_id 1개 = 확정 요구조건 1건**. 그 아래 여러 회차(build)가 누적된다.

### Step 2 — 요구조건 확정 (게이트)
- 입력한 요구사항 + 첨부 문서 + 분석 md를 바탕으로 Claude가 **요구조건 초안**을 만든다.
- 화면에서 **직접 수정**하고 “승인하고 진행”을 눌러야 코딩 단계로 넘어간다.
- 흔들리는 요구조건으로 바로 코딩 → CI 실패 반복 → 토큰 낭비를 막는 장치다.

### Step 3.5 — 코드 리뷰 게이트
- 생성된 파일을 탭으로 확인한다. 경고 배지가 있으면 특히 주의:
  - `↓` **회귀 경고**: 직전 회차 대비 라인 수 급감 — 내용 누락 확인.
  - `⚠`/`⛔` **정적 검사**: 위험 패턴(명령 실행·시크릿 등) 표시. `⛔`(high)는
    **자동 승인 모드여도** 사람 검토를 강제한다.
- “승인 → push + 검증” 또는 “거부(사유)”. 거부 사유는 다음 회차 컨텍스트로 전달된다.
- 승인 모드는 설정에서 **매번 확인(기본)** / 자동 승인 중 선택.

### Step 4~5 — 커밋/검증/반복
- 승인하면 본인 브랜치에 커밋·push하고 stage가 빌드·검증한다.
- CI 결과가 대화로 자동 회신된다. **실패면 같은 studio에서 다음 회차**로 이어가며,
  이전 회차의 실패 요약이 자동 주입되어 회차가 갈수록 개선된다.
- 진행 중 작업은 “요청 취소”로 중단할 수 있고, stage의 빌드/검증도 함께 취소된다.

### 검증 통과 후 — PR 생성 (§6.6 안 B)
- CI 통과 회차가 생기면 STUDIO 패널에 **“PR 생성”** 버튼이 뜬다.
- 누르면 본인 명의로 main 대상 PR이 생성된다(중복 생성 안 함).
- **merge는 자동으로 하지 않는다** — 반드시 사람 리뷰 후 수동 merge.

## 2. 요구조건이 잘못됐다고 판단되면
- 실패 원인이 코드가 아니라 요구조건 자체면, Step 2로 돌아가 **재확정**한다.
- 재확정하면 **새 studio_id**가 발급되고 기존 studio는 종료(abandoned)된다.
  이전 이력은 같은 세션에 남아 새 studio의 참고 컨텍스트가 된다.

## 3. 첨부 문서
- PDF/DOCX/TXT/MD 지원(파일당 20MB). 업로드 시 텍스트를 추출해 컨텍스트로 사용한다.
- HWP는 현재 미지원(안내만). 필요하면 텍스트/PDF로 변환해 첨부.
- 첨부 내용은 Bedrock으로 전송되므로, 반출 등급이 맞는 문서만 올린다.

## 4. 자주 겪는 상황
- **“AWS/GHE 재연결 필요”**: 0.1/0.2 재연결.
- **push_conflict**: 브랜치에 로컬 수정이 겹친 것. 브랜치 정리 후 재시도하거나 재생성.
- **파일 블록 없음으로 실패**: 생성 규격 미준수. 다시 시도하거나 요구조건을 구체화.
- **동시 1건 제한**: 한 번에 한 작업만 진행된다. 진행 중 작업을 끝내거나 취소 후 새 작업.
